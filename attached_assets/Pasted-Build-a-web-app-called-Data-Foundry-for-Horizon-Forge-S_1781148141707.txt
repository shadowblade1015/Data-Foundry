Build a web app called **Data Foundry** for Horizon Forge Systems.

## Product Concept

Data Foundry is a practical data curing tool that helps users clean, format, standardize, and prepare messy spreadsheet data before importing it into systems like CRMs, databases, reporting tools, or internal workflows.

The overall purpose is to take raw, inconsistent data and help users cure it into a cleaner, standardized, import-ready format.

The MVP should focus on one core workflow:

## MVP Feature: Master List Curing / List Standardizer

The main feature allows a user to upload a messy raw list and cure it against a trusted master list. The goal is to make values in the raw file match the official standards in the master list.

Example use case:
A user has a raw CSV with inconsistent school names such as:

* FIU
* Florida Intl University
* FL International Univ
* Broward Coll
* UCF

The user also has a master list with official standardized names such as:

* Florida International University
* Broward College
* University of Central Florida

Data Foundry should suggest matches, assign confidence scores, allow human review, and export a cleaned file.

## Core MVP Workflow

1. User uploads a raw CSV file.
2. User uploads a master list CSV file.
3. App previews both files.
4. User selects the raw column that needs to be cured.
5. User selects the master list column that contains the official standardized values.
6. App normalizes both columns for comparison.
7. App performs matching using:

   * exact match
   * normalized match
   * fuzzy match
8. App generates a review table showing:

   * original raw value
   * suggested standardized value
   * confidence score
   * match type
   * status
   * approve option
   * manual correction option
   * ignore/no match option
9. User reviews and approves/corrects matches.
10. App applies approved matches to the original raw file.
11. User exports:

* cleaned CSV
* exceptions CSV
* mapping CSV

## Matching Logic

Create a matching engine that works in stages:

### Stage 1: Exact Match

If the raw value exactly matches a master list value, mark it as exact match with 100% confidence.

### Stage 2: Normalized Match

Normalize both values by:

* converting to lowercase
* trimming spaces
* removing punctuation
* replacing common abbreviations
* removing duplicate spaces

If normalized values match, mark it as normalized match with 95% confidence.

### Stage 3: Fuzzy Match

Use fuzzy matching to suggest the closest master list value.

Use confidence scoring:

* 90–100: Strong match
* 75–89: Needs review
* Below 75: No confident match

Use `rapidfuzz` if building in Python.

## Export Requirements

### Cleaned CSV

The cleaned CSV should include all original columns plus:

* Standardized Value
* Match Confidence
* Match Type
* Curing Status

### Exceptions CSV

The exceptions CSV should include rows that:

* had no match
* had low confidence
* were ignored
* had blank values

### Mapping CSV

The mapping CSV should include:

* Original Raw Value
* Approved Standardized Value
* Confidence Score
* Match Type
* Approved Status

This mapping CSV can later be reused as memory for future curing runs.
